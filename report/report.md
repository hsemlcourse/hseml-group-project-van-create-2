## 1. Введение и постановка задачи

**Цель проекта:** предсказать рыночную цену б/у смартфона или ноутбука по его характеристикам. Задача актуальна для маркетплейсов (Avito, Юла) и сервисов трейд-ин - позволяет автоматически оценивать устройство без участия эксперта.

**Формулировка задачи:** регрессия. Целевая переменная - цена устройства в рублях.

**Обоснование метрики качества:**
- **MAPE**  - основная метрика. Интерпретируема как средний % ошибки, одинаково значима для дешёвых и дорогих устройств, понятна заказчику.
- **MAE** - вторичная. При близком MAPE определяет, какая модель даёт меньшую абсолютную ошибку в рублях.
- **RMSE** - контрольная. Штрафует крупные выбросы; не является приоритетной, так как датасет содержит устройства разных ценовых категорий.

При расхождении метрик приоритет: MAPE -> MAE -> RMSE.

## 2. Поиск и описание данных

**Источник данных:**
- **Смартфоны:** [Used Device Data (Kaggle)](https://www.kaggle.com/datasets/ahsan81/used-handheld-device-data) - 3 525 строк, 15 столбцов. Содержит технические характеристики и нормализованную цену б/у устройства.
- **Ноутбуки:** [Laptop Price Dataset (Kaggle)](https://www.kaggle.com/datasets/ionaskel/laptop-prices) - 1 303 строки, 12 столбцов. Цены в EUR, характеристики железа.

Оба датасета выбраны как единственные открытые источники с нужными признаками. Объединение позволяет обучить единую модель на смешанных устройствах.

**Описание датасета после объединения и очистки:**
- Итоговый датасет: ~4 600 строк, 20+ столбцов
- Признаки: бренд, ОС, диагональ экрана, объём памяти, RAM, батарея, вес, камеры, год выпуска, состояние, тип устройства
- Целевая переменная: цена в рублях (конвертирована из нормализованной формы для смартфонов, EUR→RUB для ноутбуков)

## 3. Обработка и подготовка данных

**Полная очистка:**
- **Пропуски:** удалены строки без цены (`normalized_used_price` / `Price_euros`). Остальные пропуски в числовых признаках заполняются медианой на этапе обучения через `SimpleImputer`.
- **Дубликаты:** проверка и удаление дублирующихся строк в `clean_all()`.
- **Выбросы:** обрезка 1-го и 99-го перцентилей цены - убирает нереалистичные значения.
- **Типы данных:** RAM, объём памяти и вес ноутбуков распарсены из строк регулярными выражениями, цены приведены к float.

**Работа с фичами:**
- Исходных признаков после объединения: 13
- Новые признаки: `is_laptop`, `condition_enc`, `age_years`, `camera_ratio`, `log_price`, `brand_clean`, `storage_bucket`, `ram_bucket`

**Визуализации:** см. `notebooks/01_eda.ipynb` - распределения цены, топ брендов, зависимости числовых признаков с ценой, корреляционная матрица.

**Сплит данных:**
- Стратегия: train 70% / val 15% / test 15%, случайный сплит (`random_state=42`)
- **Как избегали data leakage:** все трансформации в `build_features` - детерминированные. Статистики по целевой переменной не используются. Единственная операция по всему датасету - выбор топ-20 брендов, что не является утечкой. Сплит выполняется до обучения модели; валидация и тест не участвуют в RandomizedSearchCV.

## 4. Baseline-модель

**Модель:** Ridge-регрессия с 4 числовыми признаками (`storage_gb`, `ram_gb`, `screen_inch`, `is_laptop`), без feature engineering. Данные нормализованы `StandardScaler`.

**Результаты (val):**

| Метрика | Значение |
|---------|----------|
| MAE     | ~18 000 руб. |
| RMSE    | ~28 000 руб. |
| MAPE    | ~42% |

## 5. Эксперименты

| Модель | Гипотеза | Параметры | MAPE (val) | MAE (val) | Комментарий |
|--------|----------|-----------|------------|-----------|-------------|
| Ridge Baseline | Простая линейная модель как точка отсчёта | дефолт | ~42% | ~18k | Высокая ошибка - задача нелинейна |
| RandomForest | Ансамбль деревьев учтёт нелинейности | 200 деревьев | ~22% | ~8k | Значительный рост vs baseline |
| XGBoost | GBM лучше справится с выбросами | early stopping 50 | ~19% | ~7k | Лучше RF, медленнее LGB |
| LightGBM (num) | LGB быстрее XGB при схожем качестве | early stopping 50 | ~18% | ~7k | Подтверждено |
| LightGBM (all) | Категориальные признаки улучшат качество | + cat features | ~15% | ~6k | Лучший результат |
| CatBoost | Нативные категории vs LGB | early stopping 50 | ~16% | ~6k | Близко к LGB, медленнее |
| PCA + Ridge | Снижение размерности улучшит линейную модель | 95% дисперсии | ~38% | ~16k | Не помогло |
| Stacking RF+LGB | Мета-модель объединит сильные стороны | Ridge мета-модель | ~17% | ~6k | Сопоставим с LGB, сложнее |
| LGB tuned | Подбор num_leaves, lr, reg улучшит LGB | RandomizedSearchCV 30 iter | ~13% | ~5k | Лучший итоговый результат |
| XGB tuned | Подбор глубины и регуляризации XGB | RandomizedSearchCV 20 iter | ~15% | ~6k | Хуже LGB tuned |
| RF tuned | Подбор глубины и max_features RF | RandomizedSearchCV 20 iter | ~20% | ~7k | Хуже GBM методов |

**Перебор гиперпараметров:** `RandomizedSearchCV` с 3-fold CV на train. Для LightGBM перебирались `num_leaves`, `learning_rate`, `max_depth`, `subsample`, `colsample_bytree`, `reg_alpha`, `reg_lambda` (30 итераций).

**Уменьшение размерности:** эксперимент с PCA (95% дисперсии) в `Эксперименте 6`. PCA сохранил ~9 компонент, но Ridge с ними всё равно уступает бустингу - задача нелинейна.

## 6. Финальная модель и интерпретируемость

**Финальная модель:** LightGBM с подобранными гиперпараметрами.

**Обоснование:**
- Лучшая MAPE (~13%) на валидации после настройки
- Нативная поддержка категориальных признаков
- Скорость в 3–5 раз выше CatBoost
- Проще в деплое, чем Stacking

**Интерпретируемость:**
Топ признаков по важности (LightGBM gain):
1. `is_laptop` - тип устройства определяет ценовой диапазон
2. `storage_gb` - объём хранилища
3. `ram_gb` - объём оперативной памяти
4. `brand_clean` - бренд (Apple, Samsung значительно выше среднего)
5. `screen_inch` - диагональ экрана
6. `condition_enc` - состояние (для смартфонов)

## 7. Деплой

**Стек:** FastAPI (REST API) + Streamlit (веб-интерфейс), запускаются через docker-compose.

**Запуск:**
```bash
docker-compose run --rm train
docker-compose up api streamlit
```

**API:** `POST /predict` - принимает характеристики устройства, возвращает цену в рублях.

```
POST http://localhost:8000/predict
{
  "device_type": "smartphone",
  "brand": "Apple",
  "storage_gb": 128,
  "ram_gb": 6,
  ...
}
-> { "price_rub": 45230.0, "price_rub_formatted": "45 230 руб." }
```

`GET /health` - проверка работоспособности сервиса.

Документация: `http://localhost:8000/docs` (автогенерация FastAPI).

**Интерфейс:** Streamlit на `http://localhost:8501` - форма с параметрами устройства, кнопка «Рассчитать цену».
